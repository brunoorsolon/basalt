**Accepted stable engine baseline.** Publication and downloadable assets are tracked on the [v1.0.0 release page](https://github.com/brunoorsolon/redrock/releases/tag/v1.0.0). Stable is limited to the reviewed configuration below. This is an independent Redrock release contract, not certification of any consumer's installation or serving lifecycle.

## Known limitations and accepted exceptions

- **Kernel fault unresolved:** a prior run on kernel 7.3.4 faulted in AMDGPU during loading/cleanup. Passing on 7.3.3 with mmap does not establish the cause or fix. Do not describe this as general AMD/Linux stability or a guarantee against desktop faults.
- **Known incorrect model answer:** the accepted thinking-disabled reasoning case is still wrong. Ten fresh sessions in each of two engines using the same GGUFs, identical prompt-token IDs and greedy settings produced identical incorrect output/token sequences. This narrows the evidence away from a Redrock-only defect; it does not distinguish model, quantization or shared-component causes, and it is not a correctness pass.
- **Thinking traces are nondeterministic:** whole-response bytes and full token streams are not guaranteed identical across starts. The accepted variation requires identical correct final-message bytes and final-token suffix. Do not generalize this to arbitrary answer drift.
- **Literal framing:** the accepted literal-marker case permits interior ASCII-space variation and remains `exact_copy:false`; outer whitespace is not excused. A single enclosing JSON fence may be removed only for answer grading. These are explicit test exceptions, not exact-copy guarantees.
- **Packaging and integration:** the engine wrapper does not package the adapter or repaired ROCr. Managed installation, consumer-specific admission/serving and update/rollback integration need separate checks. Existing installed/default runtimes are not replaced by this release.
- **Rebuilds:** the recipe identifies reconstructible sources and tested outputs, not guaranteed bit-identical compiler output. A new binary, changed toolkit/runtime/model or changed configuration needs affected validation before inheriting support.

## Repaired ROCr

Stock ROCr on this host could not initialize under selected-render-only isolation: its SVM-policy loop attempted memory policy on an inaccessible GPU whose VM was never acquired. The repair filters that loop through the existing visible-GPU lookup and uses the mapped node ID for gfx-version lookup; real errors on accessible GPUs still propagate. It does not expose another GPU or change a Redrock kernel.

| --- | --- |
| Canonical source | https://github.com/ROCm/ROCR-Runtime |
| ROCm 7.1.1 base | `4e4d7abeb786e903ac2a46815ae2565de331cbd4` |
| Tested local repair commit | `f999715d0b28afdb4e9c3eb31317ff7789be54c9` |
| Reconstructed Git tree | `bf1fdc210d330b2b4aba7178b6472605327629e7` |

| Tested library | `libhsa-runtime64.so.1.18.0`, 4,088,192 bytes |
| Library SHA-256 | `63fa08fa9461d6f5e652fa50d232116b317091dbf0bbe2204799dfd705b564ca` |

The local repair is not claimed merged upstream. Base plus retained patch reconstructs its source tree without access to the private commit. In a **new, clean ROCr checkout** acquired through the authorized host transport, check out the base, verify the patch checksum, then prepare the dependency explicitly:

```sh
# ROCR_SOURCE is a new isolated checkout at the exact base above.
# REDROCK_SOURCE is the checkout containing these release records.
git -C "$ROCR_SOURCE" apply --check "$REDROCK_SOURCE/releases/patches/rocr-filtered-gpu-memory-policy.patch"
git -C "$ROCR_SOURCE" apply --index "$REDROCK_SOURCE/releases/patches/rocr-filtered-gpu-memory-policy.patch"
git -C "$ROCR_SOURCE" write-tree
# Must equal bf1fdc210d330b2b4aba7178b6472605327629e7.
python3 "$REDROCK_SOURCE/releases/check_rocr_policy.py" "$ROCR_SOURCE"
```

Commit the verified prepared tree before a build; do not apply patches at configuration or startup. The retained CPU regression extracts the actual policy loop: the original fails and the patched version skips hidden GPUs, preserves mapped-node behavior and propagates genuine policy errors. It is not a full-runtime or numerical substitute.

The tested offline build used GCC/G++ 16.2.1, ROCm LLVM/Clang 20 and CMake 4.3.0, Ninja, Release mode, `CMAKE_SKIP_RPATH=ON`, `EXPORT_TO_USER_PACKAGE_REGISTRY=OFF`, explicit ROCm LLVM/Clang CMake directories and the existing NUMA runtime. The manifest contains the full configure/build argument arrays. Matching `numactl-devel-2.0.19-4.fc44.x86_64.rpm` headers were signature-verified and extracted into a private input directory without installing the package; its checksum is recorded. Configuration and compilation ran offline, GPU-free and with read-only prepared source. No `cmake --install`, loader-cache update or host-library replacement is part of the recipe.

Retain [ROCr's NCSA notice](licenses/ROCr-LICENSE.txt) and [the thunk's MIT/BSD notices](licenses/ROCT-LICENSE.md) with any distributed dependency sources or binaries, alongside the source tree's other required notices. Do not replace stock ROCr globally. Bind this exact library and approved closure only within the consuming installation's controlled loader/namespace policy; widening device access or inheriting arbitrary library paths is not an equivalent configuration.

## Distribution and publication

The release assets are checksummed together in `SHA256SUMS`:

- `redrock-1.0.0-source.tar.gz`: the release's Redrock tree, its exact pinned llama.cpp source under `third_party/llama.cpp`, and the repaired ROCr source under `dependencies/ROCR-Runtime`. GitHub's automatic source archives omit dependency contents; use the explicit source asset for the complete combination.
- `redrock-1.0.0-linux-x86_64-gfx1201.tar.gz`: the unchanged tested `strata`, `unbiased-strata` and repaired ROCr library, with release records and notices. This is a platform-bound payload, not an installer or a self-contained runtime. The binaries retain compile-time source paths; raw qualification logs and live configuration are excluded.
- Standalone `1.0.0.json`, `1.0.0-runtime.json` and the ROCr source patch for consumers pinning identities without unpacking the archives.

Publication requires the reviewed commit, annotated `v1.0.0` tag and verified assets described in [RELEASING.md](../RELEASING.md). A draft release is staging, not publication. The binary asset preserves the engine/adapter/repaired-ROCr payloads together; the separately recorded system/vendor closure and model inputs are required, not bundled. Publication does not install, activate or change any default runtime.
